# Pin To-Do（Tauri 版）

一个 Windows 桌面任务组件：桌面上常驻一层卡片，从卡片可以打开任务面板。视觉语言取自
1971 年的终端打印件——纸张、油墨、编号、硬阴影。

本项目是 Electron 原版的 Tauri 2 重写，重写的动因是常驻内存和安装包体积，两项都下降了
大约一个数量级。

**英文版本：[README.md](README.md)**

---

## 功能

**卡片层（`overlay.js`）** — 一个无框、透明、置顶的窗口，覆盖整个工作区。任务住在贴靠
屏幕边缘的卡盒里。鼠标靠近卡盒，卡片会散布开来；每张卡片可以直接完成、计时、编辑、拖动
位置，或者钉在桌面上——钉住的卡片在卡盒收回、切换分组之后依然留在桌面。空闲时卡盒自动
收进边缘。

**任务面板（`dashboard.js`）** — 从卡盒或全局快捷键（<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>T</kbd>）打开：

- **仪表盘** — 六列网格，由用户自己拼装：时钟、统计、番茄钟、今日概览、备忘录、年度热力图、
  简短清单。拖动模块标题栏可以换位置，拖动右下角的握柄可以改尺寸，两者都会自动吸附到整列、
  整行，并且保存下来。
- **时间轴** — 竖向 24 小时刻度，每半小时一格。在空白处按下可以登记一段工作，拖动色块可以
  改时间，拖动下边缘可以改时长；重叠的记录自动分道；右侧环形图显示这一天是怎么花掉的。
- **时间线 / 月历 / 台账 / 视图** — 同一批任务的当日列表、月历格（双击某天可直接建任务）、
  以及按日期分组的台账，带搜索、优先级筛选与排序。
- **一句话登记** — 中英文自然语言：`明天三点 开会 高` 会解析成带标题、带时间、带优先级的任务。
- **番茄钟、备忘录、提醒、声音、托盘、开机自启**；六套材质，每套都有独立的昼/夜配色：
  **印刷 1971**（终端打印件：方角、硬阴影、纸张颗粒）、**餐厅 DINER**（Googie 控制台：搪瓷奶白、
  铬条、圆角）、**群青构成 IKB**（构成主义：纯平、2px 粗线、国际克莱因蓝）、**晨雾花园 GARDEN**
  （版画图志：桃红 × 鼠草绿、深青墨、金色双线内框）、**电蓝海报 POSTER**（玻璃面板、青色细线、斜切光带，
  只有「进行中的时间」给琥珀色）与**指令台 RETRO**（任务台：四角螺钉、厚实法兰边、扫描线标题条）。
  标签跟随材质的字体，所有读数一律保持等宽，这样台账的列永远对得齐；临时调色盘可按任意颜色
  token 实时预览，并按昼/夜分别保存。

日期同时带公历与农历（`9月20日 · 周日 · 农历八月初十`），并且支持按农历年重复。

## 数字

release 构建，x64，Windows 11 实测：

| | |
| --- | --- |
| 安装包 | 1.63 MB（NSIS） |
| 可执行文件 | 4.95 MB |
| 常驻卡片层 | 私有工作集约 116 MB，单进程 |
| Rust | 约 1,160 行 |
| 渲染层 | 约 12,700 行 JS / CSS / HTML |

Electron 原版需要一个 Chromium 运行时、多个进程，内存约为这里的十倍。仅加一个
`--disable-gpu` 就能让原版内存减半——这足以说明那部分开销来自合成器，而不是应用本身。

## 架构

两个窗口，一个进程，引擎是 WebView2。

| 窗口 | label | 说明 |
| --- | --- | --- |
| 卡片层 | `main` | 无框、透明、置顶、工具窗口，覆盖工作区 |
| 任务面板 | `dashboard` | 按需创建，会话内记住位置与尺寸 |

**reducer 放在渲染层**（`src/shared/data.js`），不在 Rust 里。两个窗口对同一份状态应用同一
批操作，宿主只负责落盘。这让移植的体量小了很多：Rust 侧只有窗口、托盘、快捷键和少量 Win32
调用，领域逻辑不需要跨边界写两遍。

**命中测试靠窗口区域，而不是 `WS_EX_TRANSPARENT`。** `SetWindowRgn` 同时裁剪*绘制*和输入，
所以卡片之外的区域天然穿透到桌面，不存在切换竞态。倾斜的卡片无法用矩形并集表达，因此每张
卡片根据自己的变换矩阵重建四个角，再按 4px 扫描线切成阶梯状矩形——静止时 17～24 个矩形。
不同状态留白不同：静止 8px，过渡进行中 90px，另外给浏览器判定为悬停的那张卡片留出它自身
放大所需的余量。

**只有五处直接调用 Win32**（`src-tauri/src/win32.rs`，手写 `extern "system"` 声明而没有引
`windows` crate）：光标轮询、窗口区域、窗口样式、显示器几何、前台窗口。卡片层窗口在创建后
必须被强制改成 `WS_POPUP | WS_EX_TOOLWINDOW`，而且**要一直按着**：`decorations(false)` +
`skip_taskbar(true)` 之后句柄上仍残留 `WS_CAPTION` 和 `WS_EX_APPWINDOW`，一秒后还会被工具
链改回来——表现就是桌面小组件在任务栏上多出一个按钮，以及窗口区域一清空就闪出蓝色原生标题
栏。前台轮询会把样式修回去并记录这次修复。

材质是同一条 token 轴上的第二个维度：`data-style` 选打印件还是控制台，`data-theme` 仍然选
昼夜，调色盘照旧按昼夜分别保存。

**可见性策略在渲染层**：先听用户的开关，再看全屏规则（看电影、打游戏时这块屏幕归它，卡片层
让位），最后才是可选的"仅桌面显示"。另一块显示器上的前台窗口不算遮挡桌面。

## 构建

Windows 上需要：

- Rust stable，MSVC 工具链 + Visual Studio Build Tools
- Node 18 以上
- WebView2 运行时（Windows 11 自带）

```bash
npm install
npm run build      # release 构建 + NSIS 安装包
npm run dev        # 开发模式
```

安装包在 `src-tauri/target/release/bundle/nsis/`。

`tauri build` 会 shell 出去调用 `cargo`，所以 `~/.cargo/bin` 必须在 `PATH` 里——在 Git Bash
下要写在同一条命令里，因为每个 shell 都是新开的。

## 数据

`%APPDATA%\dev.qoder.pintauri\dashboard1971-data.json` — 任务、分组、工作记录、卡片位置与
设置，每次变更即写。测试用的启动日志 `boot.log` 就在旁边。

## 测试

没有可以附加的浏览器，所以应用自带一条插桩通道：测试脚本在启动时注入窗口，通过
`API.bootNote` 把断言结果写进 `boot.log`。

```bash
pin-tauri.exe --monitor 2 --panel \
  --test-script tests/wake-distance.js \
  --test-script-panel tests/dash-assemble.js
```

`--test-script` 注入卡片层，`--test-script-panel` 注入任务面板，`--monitor` 让本进程创建的
所有窗口都落在某一块显示器上，`--panel` 在启动时直接打开面板。`tests/` 是断言：几何、区域
覆盖、拖拽行为、布局持久化。`tools/` 是从页面外部测量的探针：窗口样式、桌面像素、内存，
以及卡片层在全屏窗口面前会不会让位。

应用是单实例的：第二次启动只是给第一个实例发信号然后退出，`--test-script`、`--monitor` 这些
参数根本不会被读取，日志里也不会有任何输出——看起来就像测试静默失败。每次跑测试前请先停掉
正在运行的实例。

## 目录

```
src/                 渲染层
  overlay.*          卡片层：卡盒、散布、拖拽、钉住、区域
  dashboard.*        任务面板：仪表盘、时间轴、月历、台账、设置
  shared/data.js     reducer、查询与持久化结构
  shared/nlp.js      一句话登记解析
  shared/lunar.js    农历与农历重复
  theme.css          所有颜色都是 token
  theme-apply.js     用户自己的调色盘覆盖
src-tauri/src/       宿主
  lib.rs             窗口、托盘、快捷键、光标轮询、区域命令
  win32.rs           手写的 Win32 声明
  shell.rs           前台窗口分类
tests/               注入式断言脚本
tools/               页面外部的 PowerShell 探针
```
